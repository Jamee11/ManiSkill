# EORT 思考与隐患

最后更新：2026-07-16 17:45:00 UTC

本文件约束 ManiSkill EORT 数据构建；所有后续数据、代码、环境和实验变更必须先核对下列未解决项。

| 状态 | 项目 | 证据与要求 | 影响范围 |
| --- | --- | --- | --- |
| 未解决 | Oracle 与部署条件不可混淆 | 首版只采 simulator GT，包含新增的 2D bbox/mask-centroid supervision，输出必须标为 oracle；不得将其视作真实感知输入。后续需单独做噪声、漏检和 ID-switch 测试。 | 所有 EORT 训练与结论 |
| 未解决 | 跨机器人动作语义 | `eef_transition_local` 直接驱动 Panda 已失败，只保留为 observed dynamics。replay controller action 现可精确解码为 metric task-axis `Δxyz(m)+Δrotvec(rad)+gripper_open_fraction`，71 步反编码误差 `1.49e-8` 且真实 Panda replay 1/1 success；原 normalized command 仍保留。该证据只消除 Panda 的归一化/XYZ-Euler细节，不等于 Piper/真机 Franka 的频率、限幅、夹爪、标定或安全 replay。 | DiT4DiT/X-WAM 训练与真机适配 |
| 未解决 | 未来信息泄露与离散 phase | `future_object_delta` 在 action 时刻不可观测，只能做 dynamics 辅助目标，不能作为可部署 action condition。PushCube v2 的 phase=3 已以原生 action-aligned success 为准；DiT4DiT 当前连续 condition 路径仍会 q99-normalize state，故不得将 interaction phase/visibility/role 直接塞入该路径，需先省略离散字段或实现 embedding/mask。 | 所有 oracle gate 与模型结论 |
| 未解决 | 坐标与四元数约定 | ManiSkill pose 四元数为 `wxyz`。v2 已用 `q_target ⊗ inverse(q_reference)` 导出 rotation-vector，并有 π/2 单元测试；新任务仍必须复用该约定，不能退回分量相减。 | v2 标签与后续任务 |
| 未解决 | 数据来源与成功性 | 只接受保持原生 motion-planning 行为的成功 EORT HDF5 episode；每条导出必须携带 source path、trajectory id、action、success 和 schema version。GPU 7 上已完成 fixed/camera-rand/occluded 各 1 条的正式 harness smoke 与 disjoint seed QA，但 3 条不能代表 500/100/200 规模的成功率、存储或长时稳定性。 | Pilot 与后续批量数据 |
| 未解决 | 可重现环境 | 独立 `maniskill-eort-v1` 环境必须记录 Python、Torch、SAPIEN、ManiSkill commit/version；环境 smoke 成功前不得采集批量数据。旧的未完成 `maniskill-eort` 目录不可覆盖或删除。 | 环境与实验 |
| 未解决 | 宿主渲染后端 | 本机 CPU renderer 在 SAPIEN 场景创建时崩溃（exit 139）；采集必须保留 GPU renderer，不能以 `CUDA_VISIBLE_DEVICES=''` 强制 CPU 回退。默认 GPU 0 已出现 Vulkan buffer OOM；必须用 `MANISKILL_EORT_CUDA_VISIBLE_DEVICES` 显式选择并 smoke 指定 GPU，不能自动抢占“最空闲”设备。 | 数据采集运行 |
| 未解决 | EORT 原始视觉分辨率 | 三种 PushCube variant 的正式 harness smoke 均已验证 raw/QA 256×256→model image `(3,224,224)`；object mask 范围分别为 fixed 90–119、camera-rand 99–115、occluded 72–100 pixels。现有 128×128 pilot 不会被重写；正式大批量仍须记录峰值显存与完整 pixel 分布。 | 后续采集与视觉 tracker |
| 未解决 | 可见性分布与感知鲁棒性 | v2 已持久化 object/goal ID 并导出逐帧 visibility。Push occlusion pilot 有 163/686 object-invisible 帧；Pick 三分支 smoke 中 occluded seed 的 goal 为 0/72 可见，因而 segdepth proxy 72/72 均无效。这证明必须分别报告 object/goal/relational-valid，而不能只报 object visibility；仍未覆盖真实 detector 漏检/ID-switch、深度噪声或手/杂物遮挡。 | 数据质量与 sim2real |
| 未解决 | 相机域随机化覆盖 | `PushCubeEORTCameraRand-v1` 已验证每 episode 固定、跨 episode 随机外参；它不等于遮挡、曝光、纹理、深度噪声或真机标定误差。批量数据必须按固定/随机相机 split 报告，并保留 raw sensor extrinsic/intrinsic。 | tracker 泛化与 sim2real |
| 未解决 | 遮挡标签泄露 | `PushCubeEORTOccluded-v1` 以 `occluder_active` 仅标注 simulator visual-only occluder 的存在；它不是部署可用观测，必须永远排除在 tracker/action 输入之外，仅用于 visibility 分层 QA。 | 所有遮挡实验 |
| 未解决 | PickCube 抓取阶段的可部署性 | `PickCubeEORT-v1` 的 `is_grasped` 与 `pick_interaction_phase` 由 simulator Panda 双指接触判定产生，只能作为训练/评测标签；真机必须以夹爪开度、力/电流和视觉 track 建立独立 grasp estimator，不能把该字段输入 policy。 | PickCube、Franka/Piper 迁移 |
| 未解决 | PickCube visual split 大规模分布未验证 | GPU 7 上 fixed/camera-rand/occluded 各 1 条的采集、成功 controller replay、HDF5/sidecar/LeRobot/loader 已通过，但单 seed 无法估计成功率与可见率分布；尤其 occluded goal 0/72 可见。正式批量前必须保留独立 QA，不能直接与 Push split 合并报告。 | PickCube 泛化数据 |
| 未解决 | X-WAM 权重与数据接口可用性 | 本地源码已确认 16D proprio/14D action 的双臂 mask 接口；官方已发布约 117 GB checkpoint，但本地仍没有 `checkpoints/`，且还需 Wan2.2-TI2V-5B 基座。在下载并验证 checksum、RGB-D depth 编码、单臂 mask 和小规模 forward 前，不得把它作为已可运行基线。 | X-WAM 第二阶段主线 |
| 未解决 | 不覆盖已有数据 | 所有输出使用显式目录；默认拒绝已存在的输出路径，不删除现有数据。 | 数据安全 |
