# EORT 思考与隐患

最后更新：2026-07-10 12:21:57 UTC

本文件约束 ManiSkill EORT 数据构建；所有后续数据、代码、环境和实验变更必须先核对下列未解决项。

| 状态 | 项目 | 证据与要求 | 影响范围 |
| --- | --- | --- | --- |
| 未解决 | Oracle 与部署条件不可混淆 | 首版只采 simulator GT，输出必须标为 oracle；不得将其视作真实感知输入。后续需单独做噪声、漏检和 ID-switch 测试。 | 所有 EORT 训练与结论 |
| 未解决 | 物理接触不可由物体中心距离伪造 | 首版只导出可验证的 TCP-to-object / object-to-goal 几何量和成功状态；不产出名为 `contact` 的距离阈值标签。若需要接触，采集真实仿真接触力并验证帧对齐。 | 标签 schema |
| 未解决 | 时间对齐 | ManiSkill trajectory 的 observation/env-state 为 `T+1`、action 为 `T`。导出器必须仅写前 `T` 个当前状态，并验证每个字段长度。 | 采集与派生 |
| 未解决 | 坐标与四元数约定 | ManiSkill pose 四元数为 `wxyz`。首版仅输出向量/距离，避免直接相减四元数；新增旋转关系前必须使用相对旋转组合并加测试。 | 标签 schema |
| 未解决 | 数据来源与成功性 | 只接受 `PushCube-v1` 原生 motion-planning 的成功 HDF5 episode；每条导出必须携带 source path、trajectory id、action、success 和 schema version。 | Pilot 数据 |
| 未解决 | 可重现环境 | 独立 `maniskill-eort-v1` 环境必须记录 Python、Torch、SAPIEN、ManiSkill commit/version；环境 smoke 成功前不得采集批量数据。旧的未完成 `maniskill-eort` 目录不可覆盖或删除。 | 环境与实验 |
| 未解决 | 宿主渲染后端 | 本机 CPU renderer 在 SAPIEN 场景创建时崩溃（exit 139）；采集必须保留 GPU renderer，不能以 `CUDA_VISIBLE_DEVICES=''` 强制 CPU 回退。默认 GPU 0 已出现 Vulkan buffer OOM；必须用 `MANISKILL_EORT_CUDA_VISIBLE_DEVICES` 显式选择并 smoke 指定 GPU，不能自动抢占“最空闲”设备。 | 数据采集运行 |
| 未解决 | 覆盖/可见性 QA | 首版 schema 检查 RGB、depth、segmentation、state 和 action 的长度/有限性；后续扩大数据量前需新增对象可见率与 mask 覆盖率检查。 | 数据质量 |
| 未解决 | 不覆盖已有数据 | 所有输出使用显式目录；默认拒绝已存在的输出路径，不删除现有数据。 | 数据安全 |
